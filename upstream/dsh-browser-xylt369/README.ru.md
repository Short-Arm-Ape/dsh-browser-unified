# dsh-browser

[English](README.en.md) | [中文](README.md) | [Español](README.es.md) | [Français](README.fr.md) | **Русский** | [العربية](README.ar.md)

Предоставляет полноценные возможности веб-браузера для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`): навигация, читаемые снимки доступности (accessibility snapshots), клики и заполнение форм, работа с вкладками, создание скриншотов и вложения изображений для мультимодальных моделей.

Поддерживаемые версии хоста: **dsh `0.1.0-rc.7` / `0.1.1-rc.2`**. По умолчанию запускает локальный **Microsoft Edge** (постоянный профиль сессии + базовая маскировка автоматизации) и совместим с fake-ip DNS (Clash / Surge).

Опубликованные версии:

Репозиторий и информация о релизах: https://github.com/xylt369/dsh-browser/releases/tag/v0.8.1

## Установка

1. Убедитесь, что `dsh` установлен (`dsh --version`). Если нет, выполните: `npm i -g @deepseek-ai/dsh`.
2. Установите плагины:

```sh
dsh plugin --profile web add \
  @yeesy369/dsh-browser-playwright@0.8.1 \
  @yeesy369/dsh-tool-browser@0.7.0 \
  @yeesy369/dsh-web-permission@0.6.1
```

3. Перезапустите `dsh web`.
4. Попросите агента открыть веб-страницу в диалоге. Если сайт требует авторизации, войдите один раз во всплывающем окне Edge (сессия сохранится в `~/.dsh/edge-profile`).

Для обновления существующей установки используйте приведенную выше команду `plugin add` с указанием версий, затем перезапустите `dsh web`.

## Интерфейс настроек (0.8.x)

Настройки доступны по пути: **dsh Web → Настройки (Settings) → Конфигурация плагинов (Plugins)**. После установки и перезапуска на этой странице появятся две официальные карточки плагинов (ручное редактирование YAML больше не является основным способом).

### Шлюз веб-доступа (Web permission gate)

Управляет хостами, к которым разрешен доступ инструментам браузера и веб-запросов. Изменения вступают в силу **мгновенно** при сохранении (горячая перезагрузка).

| Элемент управления | Описание |
|---|---|
| Разрешенные хосты | По одному хосту на строку; при совпадении доступ разрешается |
| Заблокированные хосты | По одному хосту на строку; приоритет выше белого списка (по умолчанию содержит `localhost`, `metadata.google.internal`) |
| Контролируемые инструменты | Список инструментов, у которых проверяется параметр `url` (напр. `browser_navigate`, `browser_fill`, `web_fetch`) |
| Действие по умолчанию для прочих хостов | `Разрешить (Allow)` или `Спрашивать (Ask)` |
| Добавлять в белый список после подтверждения | В режиме `Спрашивать` после подтверждения пользователем хост автоматически сохраняется в белый список |

Внизу карточки доступны кнопки **Отмена** / **Сохранить**; измененные поля можно **Сбросить к значениям по умолчанию**.

### Окно браузера (Browser window)

Управляет режимом запуска Playwright и сетевой совместимостью. Изменения вступают в силу после **перезапуска dsh** или при **следующем запуске браузера**.

| Элемент управления | Описание |
|---|---|
| Режим окна | `Видимое окно` / `Скрытое окно` / `Headless (Без интерфейса)` |
| Базовая маскировка автоматизации | Включена по умолчанию (удаляет типовые следы автоматизации) |
| Разрешить fake-ip DNS прокси | Включено по умолчанию; пропускает ответы `198.18.0.0/15` от Clash/Surge |

| Режим окна | Подходящие сценарии | Примечание |
|---|---|---|
| Видимое окно | Ручная авторизация, капчи, наглядный контроль | Занимает окно на рабочем столе |
| Скрытое окно | Реальный браузер без помех на экране | Окно не отображается; требуется сессия рабочего стола |
| Headless | Серверы / CI | Сайты со строгой защитой могут распознать запуск; нет ручного входа |

Дополнительный пакет `@yeesy369/dsh-browser-settings` предоставляет боковую панель. Для повседневной настройки рекомендуется использовать карточки в веб-интерфейсе.

## Доступные модели инструменты

| Возможность | Инструмент / Действие |
|---|---|
| Открытие страниц | `browser_navigate` (с проверкой через URL-фильтр) |
| Чтение страницы | `browser_snapshot` (содержит кликабельные ссылки/ссылочные id, такие как `e1`, `f29e86`) |
| Взаимодействие | `browser_click` / `type` / `fill` / `press` / `scroll` / `wait` / `back` / `forward` |
| Вкладки | `browser_tabs` / `open_tab` / `switch_tab` / `close_tab` (изолированы по сессиям) |
| Скриншоты | `browser_screenshot` → сохраняемое вложение + ContentBlock `image` (для мультимодальных моделей) |
| JS на странице | `browser_evaluate` (по умолчанию выключен; включается явно через YAML / `cordis.patch.yml`) |

## Модель безопасности

- Разрешен только публичный `http(s)`; блокируются локальные, loopback, link-local и облачные metadata-адреса (`packages/browser-playwright/src/url-guard.ts`).
- По умолчанию разрешен fake-ip прокси (`198.18.0.0/15`); реальные частные подсети блокируются. Можно отключить в карточке «Окно браузера».
- Шлюз доступа по умолчанию разрешает неизвестные хосты; переключите в «Спрашивать», если требуется ручное подтверждение.
- Маскировка автоматизации является легковесной и не гарантирует обход всех систем защиты от ботов.

YAML / `cordis.patch.yml` остаются доступными для развертывания; веб-карточки записывают конфигурацию в то же пространство имен.

## Дополнительно: YAML / Расширенные параметры

Большинство параметров настраивается через веб-карточки. Пример YAML ниже предназначен для автоматизированного развертывания:

```yaml
# $DSH_HOME/settings.yaml — web-permission (горячее обновление)
web-permission:
  defaultAction: ask
  remember: true
```

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml
- id: browser-playwright
  config:
    windowVisibility: visible
    stealth: true
    allowFakeIp: true
- id: tool-browser
  config:
    evaluate: false
```
