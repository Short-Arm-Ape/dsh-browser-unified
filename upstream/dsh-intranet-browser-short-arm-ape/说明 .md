# dsh-intranet-browser

绕过 `@yeesy369/dsh-browser-playwright` 的 SSRF 防护。

[English](https://github.com/Short-Arm-Ape/dsh-intranet-browser/blob/main/README.md)

## 概述

本插件基于 [`@yeesy369/dsh-browser-playwright`](https://www.npmjs.com/package/@yeesy369/dsh-browser-playwright) 修改（上游源码仓库：[xylt369/dsh-browser](https://github.com/xylt369/dsh-browser/)），并保持对服务定义包 [`@yeesy369/dsh-browser`](https://www.npmjs.com/package/@yeesy369/dsh-browser) 的运行时依赖。

本插件将 **⚠️绕过原插件的 SSRF 防护**（`url-guard.ts`），以便 DeepSeek Harness 打开本地和局域网页面进行调试。它会调用独立的 Playwright 实例（独立服务名、独立配置目录、独立窗口）。

出于安全考虑，**每次 `intranet_*` 工具调用都需要用户批准**（默认 `approvalMode: 'per-call'`），且默认仍拦截云元数据端点（`169.254.169.254` 等，与原插件行为一致）。

## 与原插件的关系

| 包名 | 原插件 `browser-playwright` | 本插件 `intranet-browser` |
| --- | --- | --- |
| 服务名 | `ctx.browser` | `intranet-browser`（独立实例） |
| SSRF 防护 | 严格的 url-guard，未经修改 | 已绕过（元数据拦截保留） |
| 浏览器窗口 | 自己的 Edge 配置文件 | **另一个**配置文件（默认 `~/.dsh/intranet-edge-profile`） |
| 工具名 | `browser_*` | `intranet_*` |
| 批准机制 | 通过 `web-permission` | 内置 `ctx.approval` 门控（每次调用） |

两个浏览器可以并行运行。

## 开发与快速开始

### 1. 前置条件

- [DeepSeek Harness CLI（`dsh`）](https://www.npmjs.com/package/@deepseek-ai/dsh)：`npm i -g @deepseek-ai/dsh`
- Node.js ≥ 18 和 [pnpm](https://pnpm.io/installation)（`npm i -g pnpm`）

### 2. 构建包

在[本包的绝对路径]下执行：
```sh
pnpm install
pnpm build      # tsc → lib/，随后生成客户端 bundle → lib/client.js
pnpm typecheck
pnpm test
```

包内单元测试覆盖 URL 策略（元数据拦截、file/凭证/协议校验）与授权门决策逻辑；真实浏览器行为可参照 `browser-playwright` 的端到端模式自行验证。

### 3. 手动安装到 DeepSeek Harness（web profile）

本包通过本地路径安装，无需发布到 npm。

Windows 一键脚本：
```sh
powershell -ExecutionPolicy Bypass -File scripts/install.ps1
```

macOS / Linux 一键脚本：
```sh
bash scripts/install.sh
```

或手动执行（脚本做的正是这件事）：
```sh
dsh plugin --profile web add [本包的绝对路径]
```

如果有 DeepSeek Harness 实例正在运行，请重启它。

AI 会调用 `intranet_open`，界面弹出授权确认（默认每次调用都要授权），批准后才真正导航。之后可以用 `intranet_snapshot` / `intranet_click` / `intranet_screenshot` 等继续调试。

## 卸载

```sh
dsh plugin --profile web remove @short-arm-ape/dsh-intranet-browser
```

| 工具  | 作用  |
| --- | --- |
| `intranet_open` | 打开 http(s)（可选 file）URL；内网/本地地址允许 |

| `intranet_arm` / `intranet_disarm` | 仅 `approvalMode: 'arm'` 下有意义：一次性授权激活/停用（`per-call` 下为 no-op） |

# 配置

`$DSH_HOME/settings.yaml`（热更新；也可在 **设置 → 插件配置 → 内网浏览器** 卡片里编辑 `approvalMode` / `approvalScope` / `blockMetadata` / `blockedHostnames` / `windowVisibility` / `stealth`，其余走 YAML）：

```yaml
intranet-browser:
  approvalMode: per-call     # per-call（默认，每次弹窗）| arm（intranet_arm 激活后免弹窗）
  approvalScope: all         # all（默认，所有调用都弹窗）| navigation（只读操作免弹窗）
  blockMetadata: true        # 默认仍拦截云元数据（169.254.169.254 / metadata.google.internal / instance-data 等）
  blockedHostnames: []       # 额外始终拦截的主机名/IP（自动归一化：尾点、IPv4-mapped IPv6、整数 IP 等）
  allowFile: false           # 允许 file:// URL
  windowVisibility: visible  # visible（默认）/ hidden / headless —— 下次启动浏览器生效
  stealth: true              # 轻量反检测
  channel: null              # chrome / msedge，省略自动检测
  profileDir: ~/.dsh/intranet-edge-profile
  maxWaitMs: 60000           # intranet_wait 等待上限
  navigationTimeoutMs: 60000 # intranet_open / intranet_back / intranet_forward 导航超时
  interactionTimeoutMs: 30000 # intranet_click / intranet_fill / intranet_press 交互超时
  evaluate: false            # 暴露 intranet_evaluate（高风险）；插件加载时注册，修改需重启
```

# 语义、行为和限制

- **访问限制**：协议必须为 http(s)（以及当 `allowFile` 时的 file），不允许嵌入凭据（`user:pass@`），以及默认的元数据拦截列表。**私有 IP / 环回 / DNS 解析筛查已被移除**——这正是本插件的目的。
- **元数据黑名单在两个层面生效**：初始导航 URL（`goto` 之前）**以及浏览器上下文的每个请求**（通过路由处理器）——重定向目标、XHR/fetch、iframe 等子资源都覆盖，已授权页面无法通过 302 或脚本跳转到元数据端点。黑名单按归一化后的主机名匹配：尾点域名、IPv4-mapped IPv6、整数/十六进制/八进制 IP 变体均可命中；内置常见厂商端点（Azure `metadata.azure.internal`、腾讯 `metadata.tencentyun.com`、阿里云 `100.100.100.200` 等）。
- **授权机制**：在 `tools/pre-execute` 流程中，任何需要授权的 `intranet_*` 调用未经批准都会被拒绝（故障关闭）。当没有批准服务或没有代理时，调用也会失败。拒绝与批准服务异常都会写入日志（`[intranet-browser]`）。
- **`approvalScope: navigation`**：只读调用（`intranet_snapshot` / `intranet_screenshot` / `intranet_scroll` / `intranet_wait` / `intranet_list_tabs`）不再逐个弹窗；导航/写调用仍每次弹窗。该选项不会绕过请求级黑名单。
- **`Full access`会话自动通过**：当调用会话的批准策略为 `never`（即`Full access`）时，`intranet_*` 调用将无需提示直接通过——用户已在会话级别选择退出批准提示，这与 shell / 文件工具的可信度匹配。切换回 `ask`（即 `Workspace Write`）将恢复每次调用提示。
- **临时禁用提示**仅对**当前代理**在进程生命周期内禁用提示；重启 dsh 需要再次执行 `intranet_arm`。`per-call` 模式下 `intranet_arm` 是文档化的 no-op。
- **超时配置化**：`maxWaitMs` / `navigationTimeoutMs` / `interactionTimeoutMs` 每次调用都读取当前配置（热更新即时生效）；工具注册的超时只是宽裕的挂起保护。
- **元数据默认保持拦截**；除非在完全受控的网络中（例如明确测试 IMDS 的云 VM），否则请勿禁用 `blockMetadata`。
- 每次导航将返回 `url / title / statusCode`（与 `browser_*` 工具类似）
- 标签页按 Harness 会话隔离；**cookie 与 localStorage 通过单一持久 profile（`~/.dsh/intranet-edge-profile`）跨会话共享**——登录态属于会话间共享，请注意隐私边界。

# 模型行为

- 模型看到 `intranet_*` 工具（描述中包含 SSRF 绕过和批准提示）以及页面文本/引用/截图附件；它不会看到 Playwright 或浏览器内部细节。
- 在 `ask` 策略下，每次 `intranet_*` 调用都可能触发批准提示；描述中告诉模型不要滥用，并先说明意图。在 `never`（`Full access`）下，不会出现提示。
- 长快照消耗 token；截图以附件形式传输，不进行 base64 编码。
- `intranet_open` 返回最终 URL、标题和 HTTP 状态码，便于故障排查。
